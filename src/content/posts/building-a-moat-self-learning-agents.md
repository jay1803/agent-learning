这篇 X Article（2026-07-07，CopilotKit 创始人 Atai Barkai）的核心论点：**自我改进是新的护城河**，能让产品公司不止是 LLM API 的套壳。产品每天有成百上千甚至百万次 agent 与用户的交互，用户在其中不断“教”agent，但这些“课”大多直接消失了。作者最有价值的一个判断是：**agent 的失误和人的修正通常落在两个不同的地方，没人把它们连起来**——trace 工具只看得到 agent，监控浏览器的工具只看得到人；而唯一能同时看到两者的地方，是人和 agent 并肩工作的界面。

## 两个学习来源

- **Agent trace**：agent 每一步都记录下来——被要求做什么、调用了哪些工具、返回了什么、在哪里失败。再让另一个 agent 读这些 trace，找出失败模式，改写 prompt、工具和指令。缺的一半：agent 交互之外的活动，而大部分工作仍发生在那里。
- **浏览器里的用户活动**：也就是观察用户的点击、编辑、回复和工作流。例子是 Brex 的入职流程：观察分析师工作，把每次人工修正当作训练信号，每次修正都是一个带标签的数据点。缺的一半：它完全看得见人，却不知道 agent 尝试了什么、为什么失败。
- 只用其中一个的产品，会明显输给两个都用的产品。

## 学到的东西用在哪里

三个层面，各有取舍：**模型权重**（把经验微调进模型）、**harness**（模型周围的一切：循环、允许调用的工具、在行动前拦住它的检查）、**上下文**（把新信息直接放进 prompt，每次调用都读）。作者在前一篇文章里讲过这三层的 10 种方法。他也提醒，捕获信号之后 agent 还得会用，模型的注意力预算有限，把一切塞进上下文不是办法。

## 三类记忆

- **程序性（怎么做**）：学到的工作流和规则，类似 skill 或 agents.md。例子：经理批准了忠实客户的超额退款，agent 学会下次照做。优点是同类情况处理一致；缺点是**学错了工作流，就会每次都自信地做错**。
- **情景性（发生过什么**）：具体的过往事件，例如“1 月 5 日某人退款失败，因为卡已过期”。优点是真实案例比抽象规则更好用；缺点是大多数过往案例是噪音，需要有人筛选，否则有用的会被埋掉。
- **语义性（事实**）：稳定的事实，例如“所有信用卡方案都有额度，但额度因方案而异”。优点是到处可复用；缺点是**会悄无声息地过时**，额度一变，agent 就自信地出错。
- 一句话：语义记忆存“什么是真的”，情景记忆存“发生过的案例”，程序记忆存“怎么处理它的规则”。

## 拥有这个闭环

- 学习数据是产品最重要的部分，从零造软件的成本越低，它就越值钱；拥有它，才不只是套壳。
- 作者的方案是在界面层用 **AG-UI（Agent-User Interaction Protocol**）：一个开放标准，在应用、用户和 agent 之间实时传递每个事件（工具调用、状态变化、审批、编辑），于是 agent 的尝试和人的修正进入同一条流。他称 AWS、Google、Microsoft、Oracle、LangChain、Mastra、Pydantic AI、CrewAI、LlamaIndex 等已采用。
- 因为与框架无关，学到的上下文可以注入任何 agent，换框架不用重做集成。一个客户的界面同时接 CopilotKit 自己的 agent、Google ADK 和 Microsoft Agent Framework，记忆三者共享——**记忆与框架选择解耦，就是可移植性**。
- **自托管**：CopilotKit Intelligence 部署在客户自己的 Kubernetes 上（SOC 2 Type II、可离线隔离部署），数据和学到的东西都留在自己手里。作者把对手概括为“要么把你的学习留在他们的云里，要么像 Meta 那样靠监控获取”。

## 学习容器：新经验扩散到多远

一开启学习就会遇到的问题：一个用户的敏感事实不该泄漏到另一个用户的 agent 上下文里。CopilotKit 的做法是“学习容器”，由开发者设定每条经验的作用范围：**按用户**（个人偏好）、**按团队**（审批流程）、**按应用**（全公司规则），并且可审计——能看到学到了什么、落在哪个容器。

## 局限

- 这基本是一篇产品推广文：前半部分的框架（两个来源、三层、三类记忆）讲得清楚，后半部分的解法全部指向 CopilotKit Intelligence 和 AG-UI，并附有抢先体验报名；“已在财富 500 强生产环境运行”、各大公司采用 AG-UI 等是作者自述，没有效果数据。
- 关键难点——怎么从修正中提炼出正确的经验、怎么发现过时的语义记忆、怎么避免学到错误的工作流——文章只点出了风险，没有给出方法。“在界面里观察用户”与作者批评的“监控用户”之间的边界也没有讨论清楚。
- 文中约 10 张配图接口没有返回，总结只依据文字部分；这篇没有代码块。
