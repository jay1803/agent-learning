## 嘉宾背景

津晶是 Orca 联合创始人，做过量化投资，也曾在 Google 工作。她和联合创始人凭活动直播项目进入 Y Combinator，之后推出面向企业的 AI 软件测试产品 Stably，后来把重心转向 Agent 协作工具 Orca。访谈录制时，Orca 团队有四个人。

## TL;DR

津晶手头的 400 多个 worktree 分处不同阶段，约一半已按固定流程自动运行。她把人的注意力留在三个节点：开工时说清目标和验收标准，遇到重大决定时看方案，交付时检查成果。Orca 把不同工具的任务状态汇总起来，让人知道哪里需要介入，也能在暂时离开后迅速找回当时的进展。

## 一个人能管数百项 AI 任务，因为多数任务只在关键节点需要他介入

津晶说，开到五个 Claude Code 终端，就可能记不清每个窗口在做什么。Orca 汇总 Claude Code、Codex、OpenCode 等工具在不同 worktree 里的状态，标出哪些任务还在运行、哪些卡住了需要回答、哪些已经交付并等待验收。想找回三天前搁下的工作，可以搜会话标题、worktree 名称或 Linear 工单里的关键词，直接跳回对应终端。

有些用户会让一个主 Agent 按预设流程协调其他 Agent。从一张 Linear 工单出发，Claude Code 可以带着 Codex 等工具收集需求、写设计文档、反复审查，再实现并用浏览器或移动端模拟器测试，最后交付一个 PR 和一份 HTML 报告。人先说清想要什么、怎样算合格。如果中途需要定夺，有些用户会要求 Agent 把方案做成可浏览的页面，看过再决定是否继续。

发布和社区反馈这类重复工作可以进一步交给定时任务。Orca 的发布 Agent 每小时检查一次进度，从 Linear 和 Slack 收集内测反馈，判断该从哪个分支发布，需要津晶做决定时再给她发 Slack 消息。社区反馈也会由 Agent 每天归类，整理当天收集到的信息和待回复的问题。

## Orca 能让用户跟着日更，是因为更新后手头的工作还能继续

Ghostty 和 iTerm 的分屏给了 Orca 最初的界面灵感。津晶团队用它们同时跑多个 Agent 时发现，一次更新就可能打断所有终端会话。即使能找回历史记录，用户也得重新确认之前开着的几十个任务里，哪些已经结束、哪些仍在运行。津晶说，这让用户不太敢更新，新功能也就更晚进入日常工作。

按津晶的描述，Orca 用本地数据库保存终端会话的快照，更新后恢复会话和历史记录，让已经在跑的 Agent 和开发服务器继续运行。她说，保存和恢复快照本身相对容易，难的是追踪数百个终端的状态时还要控制内存占用。团队为此做了缓存和存储优化。她把这种连续性视为用户愿意跟着 Orca 更新的一个重要原因。

## 用户访谈能确认痛点，解决方案要靠试用来检验

津晶说，团队每做一个新项目，都会和约 100 人深入交流。做婚礼直播时，她给早期用户打电话，问他们为什么开始找这类工具、试没试过 Zoom、在类似产品上实际花过多少钱。做企业产品时，她会直接问客户或同行，公司买过什么、花了多少、最大的开销在哪里。她也提到 YC 的 Michael Seibel 对团队的要求：了解客户的收入和增长，弄清不同岗位的人各自想解决什么，以及这个问题值不值得客户拨出一笔可观的预算。用户已经试过的办法，也会成为团队设计新方案的起点。

确认用户需要掌握 Agent 的状态之后，团队还得试出状态放在哪里才有用。他们一度以为用户只会偶尔看一眼，把状态放到右侧角落，结果发现几乎起不到作用，于是换了几个位置，根据反馈反复调整。主持人问，怎么避免被声音最大的用户带偏。津晶说，团队会参考社区 PR、issue、论坛意见以及定性和定量反馈，最后由四个人做决定。拿不准时，她会让团队亲自试用，看看改动能不能提高他们自己的工作效率。

## Orca 的跨工具兼容性既是产品卖点，也是用户愿意推荐它的理由

津晶把 Harness 理解为让模型反复调用工具、推进任务的执行循环。Orca 把这一层交给 Claude Code、Codex 等现有工具，自己负责跨工具协作。用户可以保留熟悉的终端界面，直接用上原工具推出的新功能，也能在同一会话里切换到图形界面。Claude Code 用完额度时，用户可以把手头的任务交给 Codex 接着做。

面对主持人关于 OpenAI 和 Anthropic 的追问，津晶承认 Orca 与两家自带工具有许多功能重叠，眼下的功能优势很难长期守住。她更看重各家的产品动机：模型厂商希望用户留在自家工具里，Orca 则有动力让用户在不同工具之间顺畅切换。团队自己也要管理多个订阅和额度，遇到的问题会直接影响开发优先级。津晶说，录制时团队每天发一个稳定版，每版通常包含上百个 PR。

她估计，团队约 95% 的时间花在产品上。Claude Code 或 Codex 发布新功能时，他们会在 X 上演示怎么在 Orca 里用。她也把相当一部分流量归因于用户在 GitHub 上搜索 ADE 等关键词。对已经采购 Claude Code 的团队来说，推荐 Orca 时只需要演示怎样把手头的工具用得更顺。津晶更在意试用之后有多少人留下来，因为用户持续在用，才有机会把它介绍给下一个人。

## 津晶选择创业方向时，更看重需求能否反复出现

团队的第一个产品为婚礼和企业活动提供线上直播，赶上了疫情尾声的需求。产品刚上 App Store，就有陌生用户自己找来，用户和收入都在增长。YC 项目结束后，团队发现婚礼这样的场景很少复用。要继续增长，就得不断找到新客户，还要承担获客成本上涨的风险。津晶认为这个项目可以有不错的收入，但很难做到她想要的规模。

第二个产品 Stably 用 AI 做软件测试，已经有不少企业客户。团队随后看到，通用 coding agent 开始接手一些原本要用专门工具完成的工作。津晶举例说，Claude Code 可以查看视频帧、参与剪辑，还能调用 Seedance 生成视频。与此同时，有 Stably 用户问，能否用同一套方式管理通用 coding agent。团队于是把做测试时积累的 Agent 会话管理经验用到 Orca 上，转向更通用的日常协作场景。

## AI 正在改变消费应用和企业软件的创业账本

在津晶看来，企业软件过去虽然难卖，但通常能签下一到三年的合同，客户更换工具的成本也较高，收入因此相对可预期。她观察到，如今企业采购 AI 工具时，会反复衡量该买什么、该买多少用量，采购过程可能更长。有些客户走完整个流程签了约，几个月后就开始考虑怎么解约。

消费应用的投入和回报也在变。津晶说，现在有人一个月就能做出好几个应用。她看到的数据让她觉得，习惯了免费应用的消费者也更愿意为 AI 用量付费。主持人追问，应用供给大幅增加后，用户的时间和愿意安装的应用数量依然有限。津晶同意，争夺用户原本花在 TikTok 上的时间会更难。她更看好那些过去太贵、太慢或根本做不出来、现在能解决实际问题的应用。

## 津晶对 AI 的乐观取决于人能否继续提供独特价值

津晶说，两年前她更担心 AI 取代脑力劳动，后来逐渐把智能理解为多种能力。她用虎鲸和人类各有擅长的事来说明，AI 的能力也可能沿着与人不同的方向发展。如果两者能够互补，她就会把 AI 视为生产力工具，让人有余力去解决生物医疗、能源开发等领域尚未解决的问题。她也承认，有些 AI 专家可能会认为，AI 最终能在各个维度上超过人。

她对财富分配的判断也取决于这个前提。如果 AI 可以完全取代人，掌握 AI 的少数人可能认为大多数人已无法提供价值，财富也可能随之集中。如果人仍能提供 AI 欠缺的能力，她认为现有的社会分配方式就有可能延续。

主持人部分同意。他担心标准化教育长期强调容易被 AI 接手的能力，给个人兴趣和技艺留下的空间太少。他期待在 AI 环境中成长的下一代重新重视这些特长。津晶也认为转型期可能很艰难。她用历史上的技术变革说明，即使社会最终能找到新出路，一代人仍可能经历失业。主持人补充，从历史尺度看很短的五年，对个人可能正是决定人生走向的五年。

## 提到但未深入展开的话题

两人还谈到 Orca 录制时约 4.9 万颗 GitHub 星、下载量、津晶的订阅和 API 开销、团队共享的远程主机，以及用插件支持视频、PPT 和专用文件格式的设想。访谈也提到 Orca 在个人项目和股票分析中的用法，以及软硬件结合与供应链、算力托管与推理优化、AI 咨询和传统行业改造等创业方向。
