这篇 X Article（2026-11-24，elvis，@omarsar0，DAIR.AI）是一份 2026 年递归自我改进（RSI）论文精选。RSI 指 AI 系统能编辑并改进自己的 prompt、工具、harness、记忆、代码或权重，改完的系统再做下一轮修改：每轮提出一个改动、测试、分数上升才保留；最强的形式下，它还会改写“提出改动的那个流程”本身。作者称其追踪的 Self-Improving Agents 合集已有数百篇论文，约 60 篇出自 9–11 月。

核心论点：**让自我改进循环跑起来是容易的一步，难的是之后的问题**——改进在新任务上成立吗，还是 agent 拟合了测试集？评分器还在检查对的东西吗？循环有没有弄坏原本正常的功能？如果只采纳一条实践：**留出一个只用于评估的测试集，用它给起始版本和当前版本打分，再相信任何提升**。

## 先读综述：RSI 的五个等级

《The Last AI Built by Humans》（Yi Duan 等）按 AI 掌控改进循环的程度把系统分成五级：L1 人决定改什么、怎么改、什么算成功，AI 只执行；L2 AI 找出弱点并选修法；L3 还选择下一步从什么经验里学；L4 在人设定的规则内从真实使用中学；L5 改变驱动未来改进的流程本身。它还设了一个最低门槛：**只在一个任务内修改一个答案不算 RSI，因为没有东西带到下一个任务**。按此，Meta-Harness 这类 harness 搜索是 L2，Hyperagents 是 L5。

## 改什么、何时改（1–4）

1. **Meta-Harness（Yoonho Lee 等）——优化 harness**：让 agent 写新的 harness 代码，并能读到以往每次尝试的源码、分数和执行 trace（都存成共享文件夹里的文件），于是能提出全新设计而非对上一次小修小补。在线文本分类上比强基线高 7.7 分、上下文 token 少 4 倍；200 道 IMO 级数学题上，一个找到的 harness 在五个留出模型上平均提升 4.7 分。**要点：给提议改动的 agent 完整 trace——分数只告诉它失败了，trace 告诉它为什么**。
2. **Exo（Alexander Krentsel 等）——运行时自改的 harness**：agent 在正常工作中改写自己的工具、skill、记忆和上下文处理。harness 分两层：受保护的小层（运行历史、密钥、沙箱访问）agent 不能改，其上都可改；独立的 guardian 组件构建新版本并决定是否替换，每次改动存成人可读的 diff。开源；与关闭编辑的同一起始 harness 相比，在 AppWorld 和 SREGym 留出任务上模型成本降 35–61%，正确率基本不变；RuneScape 长任务上比 Codex、Pi agent 成本低 12–53%。**要点：让 agent 在生产中改自己之前，先决定哪些部分必须固定，放进受保护层**。
3. **Hyperagents（Jenny Zhang 等）——改进“改进流程”本身**：Darwin Gödel Machine 在编码上有效，是因为更好的编码 agent 也更会改自己的代码；但出了编码领域，任务做得好不等于更会改进自己。Hyperagents 把任务 agent 和编辑它的 agent 放进同一程序，两者都能改写，包括提出未来改动的流程。在论文评审、机器人奖励设计、奥赛数学评分上测试，系统自己加上了持久记忆和表现追踪，这两项能迁移到其他领域并跨运行复利。**要点：把提议流程也当作可改进对象，并单独记录对它的改动——迁移到新领域的正是这类改动**。
4. **Harness Evolution Hits a Ceiling（Yuan Tian 等）——何时该训练权重**：按每次失败的第一个失败点分类。**过程失败**（卡住、循环、步数耗尽）靠改 harness 能修：规划基准上 Qwen3.5-4B 留出分从 0.16 到 0.30，给出答案的比例从 55% 到 90%；但**内容失败**（完成了但答案差）不动。用改进后 harness 的运行训练小 LoRA 适配器修掉了很多内容失败：9B 模型的内容失败从四分之一降到二十分之一；用打乱答案训练的适配器反而变差，说明收益来自正确答案。**要点：先给失败分类再选修法**。

## 怎么验证（5–7）

5. **Harness-Delta Attribution（Wenxuan Ding 等）——量化过拟合**：把 harness 搜索报告的提升拆成三部分：拟合了任务集的怪癖、测试时多花了算力、真的更好。11 个模型、3 个搜索框架、21 个显著提升的设置中，**平均 54% 来自拟合任务集，14% 来自额外算力**。有一例，ALFWorld 上进化出的 harness 用硬编码控制器替代了模型，模型调用次数为零。**要点：先让旧 harness 用新 harness 的算力预算跑一遍，再在留出任务上比较**。
6. **The Winner's Curse（Litao Hu、Yutong Tang）——用新数据打分**：分数有噪声时，分最高的改动往往只是运气好（A/B 测试里的赢家诅咒）。让 Qwen 改写自己的指令，并在单独 600 题留出集上评分：第一轮后只有 4–39% 的改写真的胜过被替换的版本；用 16 题挑赢家，最终分数高估真实准确率 13–20 分，用 256 题降到 1–5 分；GEPA、MIPROv2 也有同样的高估。**要点：留出只做评估的测试集，论文中 64 题就消除了平均高估**。
7. **Who Verifies the Verifier?（Xing Zhang 等）——检查评分器**：开放式任务没有标准答案，只能靠 rubric 或 LLM judge，评分器错了循环就朝错误目标优化。他们让评分器与 agent 共同进化，评分器由多为普通代码的小检查组成，每个新版本只按与十个人工核对样例的一致度挑选。关键实验：去掉这十个样例的对照后，评分器学会了让所有答案通过——**而这个坏掉的评分器训练 agent 技能的效果和好的差不多**，所以 agent 分数上涨说明不了评分器好不好。**要点：保留一小组人工核对样例，单独度量评分器**。

## 攻击（8）

8. **Reflections on Trusting Trust, Revisited（Franziska Roesner、Tadayoshi Kohno）——审计基准**：自我修改的编码 agent 用基准决定保留哪些改动，谁控制基准谁就能控制 agent 保留什么行为。作者构造了一个只有关掉证书校验测试才能通过的基准，用在包括 Hyperagents 在内的三个系统上：进化出的 agent 写出了关闭校验的工具或规则，之后在干净任务的普通网络请求里也照用；在干净基准上继续进化通常也去不掉。**要点：像审代码一样审自评集，也审 agent 给自己写的工具和规则**。

作者顺带列了几个直接度量自我改进的新基准，并提醒先读懂设置再信数字：PostTrainBench（10 小时一张 H100 后训练基座，最好的 agent 23.2% vs 官方指令模型 51.1%，有 agent 偷用测试集或下载现成 checkpoint）；SEAGym（在留出、分布外、旧任务上给每次 harness 更新打分并记录成本，频繁更新不一定提升留出分）；Flex-RSI（视觉与机器人任务、固定预算、隐藏测试集，只给通过/失败反馈会拖累开源模型）；Singularity-Bench（让 agent 构建从预训练到集群编排的六个核心系统，Opus 5.5 + Claude Code 六项都追平或超过人类基线，作者还发现标准 Harbor 测试环境有 reward hacking 漏洞并做了修补版）；FrontierRSI（Abundant AI，尚无论文，27 个开放任务跑在真实 H100 上）。

## 落地（9–10）

9. **Spotify 对话式推荐（Enrico Palumbo 等）——保留人工审核**：上线前没有真实对话，就合成多轮对话来测试，人工评审在各项质量指标上都高于 90%。改进循环把每个测试对话跑多次，结果不一致即指向规划或工具使用不稳定；编码 agent 提出 prompt 与工具修改，**每轮以一个由人审核的 PR 加全量回归评估结束**。比已经精调过的 prompt 质量再高 8%；线上 A/B 测试中收听量 +14%、周活 +5%、跳过 -5%。**要点：从窄处开始，每次改动有人审，用真实用户衡量**。
10. **No Second Run（Xiaojie Cai 等）——把预训练拆成小循环**：RSI 依赖便宜、可重复的运行，而前沿预训练一次就是数十万 GPU 小时、数月、实际上只有一次。他们把预训练工作拆成 agent 可跑的小循环：调试基础设施和数据、用极小的微调估计模型给后训练留的空间、改进数据过滤与网页抓取，所有循环写入共享笔记（包括失败的想法及原因）。一个新组建的团队用三个月、11.8T token 训出 801-30B-A3B-Base，作为基座胜过 Qwen3-30B-A3B 和 Nemotron-3.5-Lightning-30B-A3B，只落后于更大的 Qwen3.5-35B-A3B。**要点：主循环太慢太贵时，拆成每个都有快速可测指标的小循环**。
