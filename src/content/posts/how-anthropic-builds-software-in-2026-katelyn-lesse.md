## 嘉宾背景

Katelyn Lesse 领导 Anthropic 的平台工程团队，负责 Claude API，以及 Claude Code、Claude Desktop 等产品依赖的基础设施。她曾在 Betterment 从软件工程师转任工程经理，后来加入 Stripe Capital，参与建设 Stripe 的贷款业务。本期《The Pragmatic Engineer》由 Gergely Orosz 主持。[节目视频](https://www.youtube.com/watch?v=9oNvKMd7xJo)

## TL;DR

Anthropic 用 Claude 加快代码实现后，得以在 Claude Managed Agents 已进入测试时重做架构，也能在不查看客户原始提示词和回复的情况下，用真实流量验证新版 Rust API。两次重做都要求工程师先说清系统应该怎样运行，再决定用什么办法验证。日常交付也沿着这条线变化：例行改动可以由代理完成并部署，风险较高的变更仍由人审查，生产故障由拥有系统的团队负责。

## Claude 降低了工程团队采用陌生语言的成本

Claude API 最初是运行在单个 Google Cloud 区域的 Python 单体服务。据 Lesse 了解，早期做 API 和应用的人很少，沿用 Python 方便他们与研究、推理和基础设施团队协作。后来拆出新服务时，团队选了兼顾效率和开发体验的 Go。随着请求量激增，云上的 CPU 越来越难扩，增开区域又带来跨区带宽压力。团队先做了基础设施和局部优化，随后有工程师提出用 Rust 争取更大的性能收益。

团队里有丰富 Rust 经验的人很少，Lesse 自己也没写过。Claude 可以处理借用检查等容易让新手卡住的实现细节，也能解释刚写出的代码，让工程师在需要时读懂它。Lesse 想起 Stripe 曾为 API 的 V2 抽象用 Java 写了一批新服务，中途决定改回 Ruby，因为预期的性能收益抵不过学习和实现所需的时间。在 Anthropic，她看到同事用 Claude 边做边学，比预期更快地适应了 Go 和 Rust。

新人也用同样的方式熟悉系统。旧 Python 系统的文档并不完整，新人会让 Claude 读代码库，生成文字说明或可逐层点开的系统导览。内部系统通过 MCP 接入，需要时也能查事故复盘等材料。Lesse 说，大多数时候，从代码库本身就可以开始理解各组件怎样配合。

## 实现变快让 Anthropic 有余地在上线前推倒重来

Claude Managed Agents 要让 API 客户能运行云端代理，也要支持 Claude Code 的网页和移动体验，让用户发起任务后可以离开设备，稍后再回来。团队最初收到请求就启动沙箱，再在里面启动 Claude Code，并用这套方案推出了网页端和 API 的早期测试版。很快，四个问题同时浮现。沙箱一停，代理也会中断。返回第一个 token 前要等沙箱和 Claude Code 先后启动。调用外部服务需要把凭据放进沙箱。每个沙箱还要占用至少一个 CPU。

团队一度尝试逐项修补，随后决定重做。新版把代理运行框架放在持续运行的服务上，把会话状态单独保存，只在需要执行任务时启动沙箱。沙箱故障时代理仍能继续运行，请求也能直接发给 Messages API，省去等待沙箱启动的时间。外部服务的凭据存放在凭据库里，由代理服务器转发请求时附上。Lesse 说，新方案平均只用原方案约三分之一的 CPU。

Lesse 同意主持人给出的估计，从提出想法、经历重做到推出，大约用了五到六个月。重做仍是个大决定，但实现提速后，团队有时间重新设计 API 和服务边界，并在公开发布前验证可靠性、安全性和延迟。

## 影子流量让团队可以凭实际行为判断 Rust API 能否接管流量

团队原本打算从 Python 单体里逐块拆出功能改写。项目启动后，一位新加入的资深工程师提出并行搭一套完整的 Rust 实现。真实请求仍由原系统对外服务，同时经由一层轻量的 Python 入口转送到 Rust 系统做影子验证。团队无法查看客户的原始提示词和回复，于是比对**请求进入推理层之前的处理结果，以及返回侧的 token 计数**。遇到难以解释的偏差，就深入推理前的各个处理环节排查。

团队逐日追踪差异率，等两套系统的表现接近一致后，逐步让 Rust 接管流量。最初仍保留 Python 入口，Rust 处理请求出错时可以回退到 Python，响应会慢一些。等团队对新系统有了足够把握，才移除这个入口。按 Lesse 的回忆，算上前期探索，一个规模较小的核心团队大约用了五到六个月。

Rust 的编译检查为代理提供快速反馈，影子流量则让工程师能根据实际请求判断业务行为是否一致。Lesse 粗估，这次迁移中，代理发起的 PR 约有八成没有被工程师逐段细读。遇到偏差，或有行为必须精确复现时，工程师还是会深入代码找原因。

## Anthropic 按风险决定哪些交付环节需要人介入

Lesse 说，工程师现在更多围绕整个项目工作。他们和 Claude 商量目标与方案，派出第一批代理。代理可以自行拆分后续任务，在 Slack 里汇报已经提交的 PR、下一步计划和需要确认的依赖。工程师可以随时介入，代理遇到阻塞也会主动找人。一个项目可能包含多份 PR，工程师只直接参与其中一部分。

每项变更都会先经过一个基于 Claude 的分类器，由它判断**是否需要人工审查、需要几个人、应找哪些团队**。例如，例行的 SDK 版本更新如果符合已知模式，检查确认能达到预期，就可以自动合并并部署。可能产生意外副作用的改动，或团队对全自动交付还没有把握的系统，仍需要人看。Lesse 说，当时能全程自动通过的变更类型还不多，团队正在逐步扩大范围。

主分支上的不稳定测试导致 CI 失败时，常驻代理可以着手修复。平台团队也在试验 QA 代理，让它按照人写下的预期持续检查系统，发现问题便提交 PR。API 值班代理跟随人类值班数月后，刚开始承担告警初筛。判断为真实故障时，它会通知值班工程师并同步诊断，有时在人打开电脑前就提出了修复办法。**目前主要是过滤告警噪声，独立处置更多真实故障仍是目标。**

公司级开发效率团队提供底层工具，平台自己的效率团队在此基础上开发 CI 和 QA 代理，一线工程师也会为遇到的具体瓶颈做工具。Lesse 观察到，随着代理承担更多交付工作，工程师花在改造工作流程和建设工具上的时间也增加了。

## 系统所属团队继续对生产质量负责

一位技术背景较强的产品经理在 Slack 里和 Claude 一起做了提示词缓存诊断功能，并把控制台里的功能推到生产。开发者可以查看缓存命中率，也能从 API 响应中了解未命中的原因。工程师可以参与审查和把关。Lesse 说，访谈时她仍会把核心 API 的改动交给工程师。

如果缓存诊断出了故障，收到告警的是拥有控制台的开发者体验团队。他们会先调查，再视情况找那位产品经理补充上下文。常驻代理自行提交的改动引发故障时，也是由系统所属团队处理。Lesse 说，这也是团队仍保持约五到十人的原因之一。团队需要有足够的人理解系统、轮值响应，并和依赖这个系统的团队协调。

Rust 迁移期间，其他团队仍在给 Python 系统加功能。一次 Beta 功能在 Rust 团队没预料到的时候正式上线，影子流量随即报出大量差异。团队随后加了静态检查，要求相关团队在 Python 和 Rust 两边同步实现新功能，并尽量缩短需要双写的时间。Lesse 说，如今工程师有更多时间花在了解彼此的计划、处理依赖和协调上线节奏上。

## 代码实现提速削弱了手写速度和项目工期的评价价值

Anthropic 在产品和平台团队的招聘中逐步取消了传统手写代码面试。Lesse 说，他们越来越常遇到在系统设计和既往项目复盘中表现出色、却过不了手写代码这一关的候选人。她认为，这与工程师日常手写代码变少有关。团队保留了系统设计和项目复盘，正在试验让候选人用代理构建系统、审查代理写的代码，或评审代理生成的设计。Orosz 指出，传统面试方便培训大量面试官，也比较容易统一评分。Lesse 说，新形式同样要让面试官容易按统一标准评分，并给出可信的判断，所以团队还在比较不同做法。

Anthropic 仍有职级、晋升和绩效评审，招聘则更偏向资深工程师。Lesse 说，以前带领一个两年的项目，多少能说明工作有多复杂。如今，像 API 迁移这样过去可能要两年的工作，几个月就可能完成。她更看重可观察的影响，比如节省了多少 CPU、延迟改善了多少，也会看负责人如何协调多个团队、处理依赖和控制上线风险。

## 代理能承担的任务越大，工程师越需要为它们解决底层问题

Lesse 认为，职业变化带来的感受取决于工程师从哪里获得成就感。享受亲手写代码、钻研语言细节的人，可能会失去日常工作中最喜欢的一部分。以解决难题为乐的人，则有机会尝试过去因为工期太长而搁置的项目。Orosz 把话题拉回预算有限的普通团队，举了航空公司 App 和报销软件的例子。他认为，这些产品过去难以排进日程的改造，如今也可能在几个月内完成。

Lesse 提到，一家做法律软件的客户正在探索把代理的任务从审阅单份合同扩大到完成整套尽职调查。过去，使用者要自己拆解流程，再把各环节逐项交给代理。要让使用者一次委托整个目标，工程师得设计多个代理如何协作、如何访问外部系统，以及它们各自拥有什么权限。Lesse 希望代理逐步承担更多维护、值班和文档工作。她认为，深谙安全、身份和基础设施的工程师仍需要提前判断，任务范围扩大后，哪些环节会先出问题，以及系统能否在出错后继续运行。

## 提到但未深入展开的话题

两人还聊到 Lesse 在大学转读计算机、在 Betterment 带队做 401(k) 产品的经历、她加入 Stripe Capital 的契机与对 Stripe 工程文化的印象，以及 Claude API 从鉴权到推理再到流式返回的请求路径，部分连接可以保持近一小时。Lesse 也谈到及时、直接地给反馈，以及 Anthropic 的同侪反馈大多对当事人可见，并推荐了《Project Hail Mary》的小说和电影。
