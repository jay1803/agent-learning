这篇论文（arXiv 2605.15156，2026-05-14，NUS / MIT CSAIL / 东京大学 / Liquid AI 等）的核心判断：给冻结的 LLM 注入新知识，不必在“RAG 检索原文”和“微调 LLM 本身”之间二选一，可以**把知识训练进一个专门的小模型，把这个模型当作可被询问的记忆**。MeMo 让大模型（Executive）只负责推理，通过子问题向小模型（Memory）取知识，因此无需 Executive 的权重或 logits，闭源 API 模型也能直接接入。最反直觉的两点：一是数据不是原文，而是由语料合成的“reflection”问答，训练目标是让小模型脱离原文、只靠参数回答；二是它对检索噪声几乎不敏感，因为根本没有“检索一堆可能无关的文档”这一步。

## 要解决的问题与三类现有方法的短板

- **非参数（RAG、ICL**）：受上下文窗口限制，对分散在多个文档里的跨文档关系综合能力差，且对检索噪声敏感。
- **参数式（继续预训练、SFT**）：昂贵、灾难性遗忘、倾向记忆训练分布而非可迁移知识，闭源模型无法使用。
- **潜在记忆（AutoCompressor、Gist、ICAE**）：压缩成软 token，但与产生它的模型强耦合，不能跨模型、不能用于黑盒 LLM。
- MeMo 想同时满足：基座 LLM 冻结、无检索索引、黑盒兼容、无灾难性遗忘、记忆大小固定、可跨 LLM 迁移（论文 Table 1 逐项对比）。

## 做法一：用五步流水线把语料变成 reflection 问答

由 Generator 模型（实验用 Qwen2.5-32B-Instruct）对每个文档分块处理：

1. **事实抽取**：对每个块做“直接抽取”（明说的事实）和“间接抽取”（推断出的信息）。
2. **整合**：把共享同一背景（实体、时间、关系类型）的问答合并成覆盖多个事实的问答。
3. **验证与改写**：检查每条问答能否脱离原文独立理解（如“他们提出了什么？”这类代词指代不合格），不合格的用原文改写，仍含糊的丢弃。
4. **实体浮现（entity surfacing**）：问题里只给出实体的属性和关系，答案是实体身份。目的是缓解**反转诅咒**，让模型能从间接描述反推出实体。
5. **跨文档合成**：在话题相关的文档组里找“汇聚线索”（多个文档对同一实体各给一部分事实）和“平行属性”（不同实体共享某属性），生成需要多个文档才能回答的问答。

注意：问答里不嵌入任何文档 ID 或水印，避免 Memory 模型走捷径。

## 做法二：Memory 模型的训练

- 从小模型初始化（如 Qwen2.5-14B-Instruct，对比 1.5B），在 reflection 问答上做 SFT，只对答案 token 计算损失，**训练时从不接触源文档**，强制模型把知识内化到参数里，而不是学会“复制检索到的上下文”。这是它与 RAG 读取器的本质区别。
- 训练超参：3 个 epoch，学习率 2×10⁻⁵，DeepSpeed Stage 2。

## 做法三：推理时的三阶段结构化多轮协议

Executive 把 Memory 当“知识神谕”，按三阶段提问：

1. **Grounding**：把查询拆成若干原子化、探测单个线索的子问题，Memory 各自独立回答（不共享上下文）。
2. **实体识别**：基于这些回答，多轮追问以收敛到单一候选实体（用到实体浮现数据）；若找不到候选，则直接用第一阶段的回答合成答案。
3. **答案寻找与合成**：围绕已识别实体追问支持事实，最后综合成答案。

Memory 返回的是简短自然语言片段，长度与语料规模无关，所以**推理成本与语料大小无关**。

## 结果

评测基准：BrowseComp-Plus（300 题，3,541 文档）、NarrativeQA（293 题 / 105 个长文档）、MuSiQue（1,000 题，5,296 文档）。基线：BM25、NV-Embed-V2、HippoRAG2、Cartridges；上界是 Perfect Retrieval。Executive 用 Qwen2.5-32B-Instruct 或 Gemini-3-Flash，Memory 为 Qwen2.5-14B。

| 基准 | Executive | MeMo | 最强基线 | Perfect Retrieval |
| --- | --- | --- | --- | --- |
| NarrativeQA | Qwen2.5-32B | 26.85% | 21.39%（HippoRAG2） | 51.42% |
| NarrativeQA | Gemini-3-Flash | 53.58% | 26.62%（NV-Embed-V2） | 60.41% |
| MuSiQue | Qwen2.5-32B | 48.30% | 42.17%（HippoRAG2） | 62.83% |
| MuSiQue | Gemini-3-Flash | 58.70%（正文）/ 60.20%（表） | 57.00%（HippoRAG2） | 73.00% |
| BrowseComp-Plus | Qwen2.5-32B | 54.22% | 56.11%（HippoRAG2，略胜） | 79.67% |
| BrowseComp-Plus | Gemini-3-Flash | 66.67% | 66.33%（HippoRAG2） | 88.33% |

- **NarrativeQA 优势最明显**（长文档、复杂关联，Gemini-3-Flash 下 53.58% 接近上界 60.41%）；BrowseComp-Plus 的答案不在 Executive 的参数知识里，更依赖直接看原始证据，所以 Qwen 下 MeMo 略输 HippoRAG2。
- **对噪声稳**：加入等量的干扰文档后，NV-Embed-V2 和 HippoRAG2 在 BrowseComp-Plus 上掉约 6.2 个点，在 MuSiQue 上掉约 4.8–5.2 个点；MeMo 分别是 +0.55 和 −1.77（在一个标准差内）。
- **Plug-and-play**：同一个 Memory 模型换更强的 Executive，三个基准分别提升 12.45、26.73、11.90 个点，无需重训。
- **Memory 模型大小**：14B 一致优于 1.5B；换 Gemma3-1B、LFM2.5-1.2B 等同量级不同家族影响不大，说明对模型家族不敏感。

## 持续接入新语料：模型合并

对两个互不重叠的 NarrativeQA 子集各训一个 Memory 模型，再用任务向量合并（TIES、DARE 等共 14 种配置）。累计算力约 48 与 72（8×H100 GPU 小时）之比，节省 33%；K 个语料时合并是 Θ(K)、全量重训是 Θ(K²)，K=10 时约 5.5 倍节省。但代价明显：最佳配置（TIES，ρ=0.3）比全量重训低 11.0（Qwen）/ 19.1（Gemini）个点，最差的 SLERP 只有 7.85%；不过仍然高于所有检索基线。

## 局限与我的保留

- **论文自述的局限**：每个新语料都要先付训练成本；Memory 的容量有限，作者推测足够大或信息密集的语料会超出固定大小模型的压缩能力（实验里还没看到容量到顶的迹象）；跨领域、跨 LLM 家族的表现未验证。数据合成流水线第 5 步复杂度为 O(k·C²·Q²)，很贵。
- **评测规模偏小**：语料最多几千篇文档，且 BrowseComp-Plus 和 MuSiQue 的干扰文档只加到 1 倍；“检索成本与语料大小无关”成立的前提是 Memory 能装下语料，这正是尚未被验证的地方。
- **幻觉风险没有量化**：Memory 靠参数回答，可能编造；论文主要报告准确率，没有单独分析错误类型。此外论文也提醒，把文档训练进模型会带来归属追溯和访问控制问题（谁的文档能被问到）。
- **评分器**：由 Gemini-2.5-Flash-Lite 通过 DeepEval 判断对错；Gemini-3-Flash 只跑了单次，没有方差。正文与表格里 MuSiQue 的 Gemini 数字有出入（58.70% 与 60.20%），上表两个都列出，以论文表格为准需要看原文勘误。
